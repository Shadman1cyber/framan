# کافه فرمان — Farmans Cafe Platform

A complete café ordering and management platform: QR menu, online ordering, table/takeaway workflows, ratings, inventory, RBAC (customer / cashier / owner), an optional AI assistant & accountant (Zhipu GLM-4), financial dashboard, data import from accounting software, and Dockerized deployment.

Persian (RTL), warm premium café aesthetic.

## Quick start

```bash
./run.sh            # development server
./run.sh --prod     # production build + start
./run.sh --docker   # Docker Compose
```

`run.sh` checks Node/Docker, installs dependencies, creates `.env` (with a generated secret), syncs the database, seeds it if empty, and starts the app.

Manual alternative:

```bash
npm install
cp .env.example .env
npx prisma db push
npm run db:seed
npm run dev
```

## Configuration (`.env`)

| Variable | Default | Description |
|---|---|---|
| `PORT` | `3080` | Application port (**never 3000**). Single source of truth. |
| `DATABASE_URL` | `file:./dev.db` | SQLite database |
| `NEXTAUTH_URL` | `http://localhost:3080` | Auth callbacks |
| `NEXTAUTH_SECRET` | — | Auth secret (auto-generated by `run.sh`) |
| `PUBLIC_APP_URL` | *(auto)* | **QR base URL**. Set to e.g. `http://192.168.1.100:3080` so phones on your LAN can open the menu. When empty, the machine's LAN IP is auto-detected. Explicit value always wins; never localhost. |
| `AI_ENABLED` | `false` | Master AI switch (also toggleable in the admin UI) |
| `AI_PROVIDER` | `zhipu` | AI provider (extensible registry) |
| `AI_MODEL` | `glm-4` | Model identifier |
| `ZHIPU_API_KEY` | — | **Server-side only.** Never exposed to the frontend. |
| `AGENT_ENABLED` | `false` | Agent execution engine (reads + proposals) |
| `AGENT_WRITES_ENABLED` | `false` | Business-write tools (order status/price/inventory — always approval-gated) |
| `AGENT_WORKSPACE` | `false` | Unified AI workspace UI at `/admin/workspace` (R01); legacy `/admin/ai` stays when off |
| `AGENT_CAFE_ID` | — | The single Cafe ID the agent is scoped to (fail-closed otherwise) |
| `AGENT_SHADOW_MODE` / `AGENT_CANARY_USERS` | — | Gradual-release flags (see `docs/agent-runbook.md`) |
| `OPENOBSERVE_TRACES_URL` | — | OTLP/HTTP endpoint, e.g. `http://openobserve:5080/api/default/v1/traces` in Compose |
| `OPENOBSERVE_AUTHORIZATION` | — | `Basic <base64 user:password>` — server-side only |
| `OPENOBSERVE_DASHBOARD_URL` | `http://localhost:5080` | Owner-facing telemetry dashboard link |
| `ZO_ROOT_USER_EMAIL` / `ZO_ROOT_USER_PASSWORD` | — | OpenObserve bootstrap login (Compose service; server-side only) |

## Roles & permissions (server-enforced RBAC)

| Permission | Customer | Cashier | Owner |
|---|:-:|:-:|:-:|
| Menu, cart, orders, ratings, preferences | ✓ | — | — |
| View orders, change order status, tables | — | ✓ | ✓ |
| Moderate ratings | — | ✓ | ✓ |
| Products / categories / inventory / staff / allergens / QR / users | — | — | ✓ |
| Financial dashboard, AI assistant, data import | — | — | ✓ |

Enforced in API routes (`guard()`), middleware (`src/middleware.ts`), and layouts — not just hidden in the UI. Management accounts cannot use customer shopping (cart/checkout redirect to the admin panel; order placement API rejects them).

## Order flow

- **Takeaway:** در انتظار تایید → تایید شده → در حال آماده‌سازی → **آماده تحویل** → تکمیل شد
- **Table:** در انتظار تایید → تایید شده → در حال آماده‌سازی → **آماده سرو** → تکمیل شد

State transitions are validated server-side: table orders can never enter "آماده تحویل". Statuses are advanced with action buttons in the admin orders page.

## Key features

- **Search** — home-page search bar with live Persian-aware autocomplete (products, categories, ingredients).
- **Preparation estimate** — `OrderPreparationEstimator` computes a minute **range** from chef/staff counts, active order load and item complexity; shown to the customer and stored with the order (`estPrepMin/Max`, `prepFactors`) for later analysis.
- **Coffee lines** — configurable per-product coffee lines (House Blend, Ethiopia…) each with its own price; selection updates the price, is stored on the order item, and history preserves the purchased price.
- **Ratings** — public viewing; submitting requires login (redirects back to complete the rating); post-order CTA on completed orders; one rating per user per product (resubmission updates).
- **Allergens** — exactly two states: **حاوی است / حاوی نیست**. No "may contain / unknown" anywhere.
- **Inventory** — raw materials with unit, stock, min threshold, unit cost, supplier; products define internal consumption quantities (never exposed to customers); low-stock alerts.
- **AI assistant (optional)** — Zhipu GLM-4, enabled/disabled by management in the UI; controlled context builder sends only relevant business data; read-only; deterministic alerts (inventory/operations) work even when AI is off; fails gracefully.
- **AI agent workspace (optional, owner-only)** — one unified Persian RTL workspace (`/admin/workspace`, feature-flagged) that replaces the separate chat + console: conversations with rename/archive and a read-only labelled legacy archive, bounded multi-step plans executed by a durable SQLite-backed worker with lease/recovery, business write tools (order status, price, inventory) gated by explicit approval cards binding target/before/after/version/expiry, private file attachments (CSV/XLSX/text-PDF with scanned-PDF detection) and source-backed report artifacts (CSV/XLSX/SVG). Telemetry flows to a local OpenObserve instance (`/admin/monitoring`). See `docs/agent-workspace-result.md` and `docs/agent-runbook.md`.
- **Financial dashboard** — today/week/month revenue, order counts, AOV, revenue by product/category, best/worst sellers, takeaway-vs-table split, low-stock replacement cost. Does not fabricate cost/profit data.
- **Import** — CSV import (products, ingredients, orders, expenses) with Persian-header mapping, validation, conflict warnings, preview → confirm → report. Extensible to other accounting providers.
- **Image uploads** — multi-image upload from device with preview, primary image, type/size validation; served via `/api/uploads/*` (no filesystem paths exposed); storage abstracted for future S3.
- **QR** — generated against `PUBLIC_APP_URL` (or auto-detected LAN IP), never localhost; app binds `0.0.0.0` in Docker so LAN devices can connect.

## Docker

```bash
./run.sh --docker
# or
PORT=3080 PUBLIC_APP_URL=http://192.168.1.100:3080 docker compose up --build -d
```

Volumes `db-data` and `uploads` persist the SQLite DB and images. Secrets stay in `.env`, never baked into the image.

## Architecture

```
src/
  app/                    # Next.js App Router (customer + /admin pages + /api routes)
  components/             # menu, cart, admin, UI components (RTL café theme)
  lib/
    constants.ts          # roles, permissions, statuses, labels, units
    guards.ts             # session + RBAC helpers
    orders.ts             # order type-aware state machine + creation
    estimator.ts          # OrderPreparationEstimator (v1 heuristic, AI-ready)
    cart.ts               # pricing incl. coffee lines
    analytics.ts          # financial/operational reporting services
    ai/                   # provider, context builder, service, insights, settings
    storage.ts            # image storage abstraction
    importer.ts + csv.ts  # data import pipeline
prisma/schema.prisma      # SQLite schema
Dockerfile, docker-compose.yml, run.sh
```
